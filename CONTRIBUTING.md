# Contributing

Thanks for taking the time to improve CAN CRC Checker.

## Setup

```bash
pip install -r requirements.txt
pip install -e .

cd frontend
npm ci
```

The bundled example is the only project data in the repository (it is
generated by `examples/generate_example.py`); never commit customer traces,
DBC files or DataID workbooks.

## Local checks

Run the same gates CI runs before opening a pull request:

```bash
pytest --tb=short --cov=crc_checker --cov=cli --cov=webapp \
  --cov-report=term --cov-fail-under=80
pylint $(git ls-files '*.py')          # must stay at 10.00/10

cd frontend
npm run lint
npm run format:check
npm test
npm run test:component
npm run build                          # also mirrors dist into webapp/static/dist
```

`pylint` is pinned in `requirements.txt` (3.3.9) so the pre-push hook and CI
agree. CI additionally runs Python 3.9/3.11/3.13, Windows, the wheel smoke
test and the committed-`dist` freshness check.

## Conventions

- Code comments, docstrings and CLI messages are English.
- User-facing product text is Chinese: the HTML report, the web UI and web API
  error messages. The tests assert those literals byte-for-byte.
- Signal-name conventions live in `crc_checker/data/patterns.yaml`; DataID
  workbook layouts live in `crc_checker/data/dataid_mappings.yaml`. Add a
  configuration entry before adding code.
- New CRC algorithm: add a preset to `crc_checker/crc/presets.py`, its
  validation status, and a known-answer test.

## Pull requests

- Keep the change focused; describe the failure it fixes or the capability it
  adds.
- Add or update tests for behavior changes.
- Run the local checks above (the pre-push hook runs the backend ones).
